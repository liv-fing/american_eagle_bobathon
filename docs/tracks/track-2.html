Program-Level Explanation & Modernization

~15 min IBM i Developer mode RPG Modernization workflow
Explain and modernize FRS409 — the Order Modification Confirmation Window — from classic OPM RPG to modern free-format ILE RPG, then compile it directly on your IBM i.
2.1 — Understand FRS409
IBM i Developer mode
1
Open FRS409 in the Object Browser
In the Object Browser, expand the FLGHT400 filter → qrpgsrc source file, and click frs409.rpg to open the source in the editor.
💡 Notice the classic fixed-format OPM RPG style: F-specs at the top, indicator definitions, a workstation data structure (WSDS), *ENTRY PLIST with two parameters (ORDER# and ENDYN), and a DOUEQ / CASEQ dispatch loop handling F3, F12, and Enter keys.
2
Open Bob chat and verify IBM i Developer mode
With FRS409.RPG open in the editor, open the Bob chat panel, click the mode selector at the bottom, and choose IBM i Developer.
3
Ask Bob what the program does
With FRS409 open in the editor, type in the Bob chat:
What does this program do?
Bob will explain that FRS409 is the Order Modification Confirmation Window — an OPM RPG program that displays a confirmation popup when a user modifies an order. It handles F3 (Exit), F12 (Cancel), and Enter key inputs via a DOUEQ loop with CASEQ dispatch subroutines.
4
Review the output Bob gives
Bob reads the open source member and returns a complete breakdown of what FRS409 does.
2.2 — Modernize FRS409 Using the RPG Modernization Workflow
1
Ask Bob to modernize the program
With FRS409 still open in the editor, type in the Bob chat:
Can you modernize this program using the RPG Modernization workflow?
Bob recognizes the fixed-format OPM RPG code and launches the RPG Modernization (Fixed to Free Format) workflow. Choose Start workflow.
💡 You can also launch the workflow manually: click the workflow icon at the top of the Bob panel and select RPG Modernization (Fixed to Free Format). Make sure your scope is set to Library List (QSYS) so Bob targets the IBM i source.
Click the workflow icon at the top of the Bob panel to launch workflows manually
2
Fill in the workflow form
The workflow form opens. Fill in the details:
  • Source file: FLGHT4nn/QRPGSRC
  • Source member: FRS409 (Bob pre-fills from the open editor)
Accept the other defaults and click Analyze Member. Bob will spin up a subagent to convert the fixed-format RPG to modern free-format ILE RPG, then run the Code for IBM i compile action for ILE RPG, triggering a CRTBNDRPG command on your LPAR. Watch the output in the terminal panel.
3
Confirm the output location
When Bob prompts "Confirm Output Member Location", ensure the path contains your library number. Approve the requested tasks. Bob will place the modernized source at FLGHT4nn/QRPGLESRC/FRS409.RPGLE.
4
Review and Approve tasks
Bob analyzes the intermediate source file and generates a detailed conversion plan presented as a Todo List.
  • Review the proposed plan carefully to ensure it aligns with your intended modernization approach.
  • Once the plan has been reviewed, click Approve todo tools for task.
  • Bob will begin executing the conversion workflow.
During implementation, Bob may request approval before performing certain actions such as writing files, running compile commands, or fixing errors. Review these requests and approve them as needed to allow Bob to continue the modernization process.
2.3 — Review the Modernization Summary
1
Bob automatically generates a Modernization Summary Report in the chat, including: what was changed and why, lines of code before vs. after, opcode-by-opcode conversion notes, and the compilation result.
✅ At the bottom of the Bob chat panel, click the File Changed item to see the diff for FRS409.RPGLE. In the Object Browser, right-click FRS409.PGM → Detail to check the new compile timestamp. You can copy the report to FRS409-Modernization-Report.md in your workspace.
