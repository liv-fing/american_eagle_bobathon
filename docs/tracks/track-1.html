📦 IBM Bob Premium Package for i (PPi) — two features that change how you work with large codebases:
  • /init — scans your library once and writes a persistent AGENTS context file. Every subsequent Bob session reads it automatically, so Bob always knows your source layout, compile conventions, and project-specific gotchas without re-reading source each time.
  • Understand — builds a persistent, scanned dependency graph of your entire application. Instead of feeding source members to the AI, Bob queries the pre-built metadata: object inventory, inbound/outbound dependencies, signals, and usage statistics are answered instantly from the scan.

Together, these two features make IBM i modernisation tasks more accurate and dramatically cheaper in Bob Coins — Bob reasons from structured metadata rather than consuming tokens re-reading hundreds of source members on every question. Less token usage, deterministic dependency data, and shared metadata across your whole team: this is what PPi is designed for.

1.2 — Initialize Bob's Context with /init

New feature of IBM Bob Premium Package for i — /init works in QSYS (library list), IFS, and local workspace modes.

An AGENTS.md file gives Bob persistent, project-specific context about your codebase — source file layout, compile conventions, naming patterns, and critical gotchas. Instead of rediscovering your project from scratch each session, Bob reads this file first and immediately knows how your library is structured, which source files contain what, and what to watch out for.

1
Set your current library first
In the Code for IBM i sidebar, expand User Library List. Right-click FLGHT4nn and select Set as Current Library.
⚠️ Without a current library set, /init will prompt you to set one and stop. IBM-supplied system libraries (QGPL, QTEMP) cannot be used.
FLGHT4nn shows the Current Library badge in the User Library List
2
IBM i Developer mode
Run /init
In the Bob chat panel, confirm you are in IBM i Developer mode with scope set to Library List (QSYS). Type /init in the chat and press Enter.
💡 Slash commands: The / prefix triggers a Bob built-in action. Typing / followed by a command name tells Bob to run that specific action rather than treating it as a regular chat message.
Run /init in IBM i Developer mode with Library List scope
Bob will scan your library — measuring source files, member types, service programs, IWS web services, naming conventions, and database objects — then create a QBOBSRC source physical file in FLGHT4nn (if it does not exist) and write an AGENTS member at FLGHT4nn/QBOBSRC/AGENTS in Markdown format. Bob may ask for your approval at points during the process — click Approve to continue.
3
Explore the result
Open the Object Browser, expand FLGHT4nn → QBOBSRC, and click agents.md to view the generated member. It contains IBM i–specific facts discovered directly from your source — compile conventions, legacy logical files to avoid, function key constants, and non-default compile parameters.
Find QBOBSRC in the Object Browser and open agents.md
From this point on, every new Bob session in this library automatically reads FLGHT4nn/QBOBSRC/AGENTS and starts with full context about your application — no repeated setup required.
1.3 — Understand: Application Map & Dependency Analysis

New feature of IBM Bob Premium Package for i. The Understand Dashboard scans your IBM i library and builds a live dependency graph of every program, file, service program, menu, and command — without you reading a single line of source.

💡 Metadata Database & Multi-Developer Sharing: Understand is configured with a metadata database (library) to store the scanned application metadata. In a team environment, this metadata library can be shared across multiple developers so everyone benefits from a single scan, assuming each developer has the necessary authority to access the 'understand' library (ex: BOBLIB). For these labs on a shared IBM i, each lab practitioner can also create and use their own metadata library (e.g., BOBLIBnn, replacing nn with your assigned number), though in practice it could be shared.
1
Open the Understand Dashboard
In the Activity Bar, click the Understand icon. Alternatively, open the command palette with Cmd+Shift+P (macOS) or Ctrl+Shift+P (Windows/Linux), type "get started with understand", and select IBM Bob Premium Package for i: Get Started with Understand.
Click the Understand icon in the Activity Bar
Type "get started with understand" in the command palette and select the IBM Bob Premium Package for i option
2
Install the Understand Component
If not already done, install the Understand Component on IBM i, specifying the 'understand' library and other necessary information.
Click Install Understand
You will then see a pop up confirming whether you wish to proceed with the Understand installation — click Proceed.
Click Proceed to confirm the Understand installation
3
Adding an Application
If no application exists yet, click New Application, name it FLGHT4nn (replace nn with your number), add your application library FLGHT4nn (the library containing compiled objects, not source) and metadata library BOBLIBnn, then click Scan. The scan takes about 30–60 seconds.
Click New Application
Enter the application name and library, then click Add application
Click Scan
If an application named FLGHT4nn already exists and shows SCANNED, skip directly to the next step.
4
Explore the application inventory
Once the scan completes, the dashboard shows a summary of every object in the application. Review the inventory and answer these questions — the numbers are shown directly on the dashboard:
Question Where to look
How many programs are there?Objects panel — PGM row
How many are OPM (legacy RPG/CL) vs ILE?Objects panel — OPM/ILE column
How many physical files (tables)?Objects panel — FILE / PF row
Are there any service programs?Objects panel — SRVPGM row
Is there any dynamic SQL?Insight panel — Dynamic SQL risks
💡 What you should find for FLGHT4nn: ~42 programs (39 OPM, 3 ILE), 15 physical files, 6 ILE service programs (the REST API layer), and 0 dynamic SQL objects. These numbers confirm this is a classic OPM RPG application with a modern REST layer added on top.
5
Identify the most referenced objects
In the Insights tab, explore the Most referenced objects list. It shows which objects have the most inbound dependencies — these are your highest change-risk objects. Note which types of objects appear at the top and what that tells you about where the application's core data dependencies lie.
6
IBM i Developer mode
Ask Bob more about the application
Verify that you are in IBM i Developer mode, set the scope to your library list, and ask:
What are the high-level functional areas of FLGHT4nn?
Bob activates the understand-app-overview skill and uses the Understand scan data to return an application overview — functional areas, key programs, and architecture diagrams — without reading individual source members.
💡 Tip: The Understand component and Documentation (IBM i Documentation RAG-based tool) can be leveraged across all other steps and exercises (such as Documentation, Refactoring, and Testing). Make sure to enable both Documentation and Understand in the Permissions menu for each Bob Task (chat) to fully leverage these capabilities.
✅ What Understand tells you in under 5 minutes: Map programs, files and dependencies. Find the most referenced objects, reveal dependencies, and review dynamic SQL, triggers and foreign keys.

1.5 — Generate an Entity Relationship Diagram
IBM i Database mode
1
Switch to IBM i Database mode using the mode selector. Type the slash command below so /erd is highlighted in the Bob chat. Replace 4nn with your number.
/erd FLGHT4nn add this to FLGHT4nn_ARCHITECTURE.md
Bob will introspect the physical files (FLIGHTS, ORDERS, CUSTOMERS, AGENTS, etc.) and generate a Mermaid ERD. Key relationships: ORDERS links to FLIGHTS, CUSTOMERS, and AGENTS; FLIGHTS references FRCITY and TOCITY. Copy the ERD to your architecture document.
